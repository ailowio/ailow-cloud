## Fornecedor / terceiro (AUD-68)
Nenhum nesta interface (Prometheus e Grafana serão auto-hospedados na VPS, S14; ainda não existem).

## Ferramentas que falam com a API só em teste (não são interfaces de produção)
- **k6** (`scripts/carga.sh`, `ops/k6/carga.js`): roda contra um ambiente **efêmero** (banco e API subidos pelo próprio script, segredos aleatórios descartados no fim). Nunca aponta para produção. No CI: job `carga-smoke` em todo PR; carga completa e estresse só por `workflow_dispatch` (manual). **Nada agendado.**
- **Schemathesis** (`scripts/contrato.sh`): idem, ambiente efêmero.

**Evidência em produção (S14c, 2026-11-12/13):** I-03: `/health` 200, `/metrics` 404 pela internet, HSTS `max-age=31536000`, http→https 308, certificado Let's Encrypt válido; I-02: os 4 fluxos do E2E passam pelo domínio (venda em 5 toques, limite 8); I-04: `publicar.yml` verde na `v0.1.0`, digests registrados no release; I-05: backup real → Drive cifrado (nome e conteúdo ilegíveis no armazenamento cru) e restore-ensaio a partir dele. **I-01 (`/metrics`) segue sem scraper:** Prometheus não foi instalado na VPS.

Controles de integridade: I-02/I-03 sem estado próprio (proxy puro; erro da API passa como está). I-04: a tag só publica se apontar para commit da `main` e as duas imagens passarem no Trivy (CRITICAL/HIGH corrigíveis). I-05: o script recusa remoto sem `crypt`, recusa dump sem tabela com dados, confere o tamanho no remoto e só então aplica a retenção; conciliação = o ensaio de restauração (`backup.md §4`). **Fornecedores/terceiros (AUD-68):** Google (Drive e OAuth), GitHub (Actions, GHCR), Let's Encrypt e healthchecks.io: nenhum recebe dado de negócio em claro; o Drive só vê dado cifrado e o healthchecks só vê o ping e o nome do host.
